# YOUmi

**منصة جزائرية للتجارة الإلكترونية تربط المشترين بالمورّدين وتساعدهم على إدارة المتاجر والبيع بالجملة.**

واجهة YOUmi مبنية باستخدام React وTypeScript، وتعمل مع واجهة خلفية بـ PHP وقاعدة بيانات MySQL. يتضمن المشروع أيضًا إعدادًا لتشغيل التطبيق على Android باستخدام Capacitor.

| | |
|---|---|
| الموقع | [youmi.wuaze.com](https://youmi.wuaze.com) |
| المستودع | [aymencharaf/youmi-gro](https://github.com/aymencharaf/youmi-gro) |
| اللغات | العربية والفرنسية |

## الميزات

- حسابات المشترين والمورّدين ولوحة إدارة المنصة.
- إنشاء المتاجر وإدارة المنتجات والطلبات والقسائم.
- واجهات المتاجر وعرض المنتجات والشراء.
- إدارة الاشتراكات والإعلانات وطرق الدفع التي يضبطها مدير المنصة.
- YOUmi Reels لعرض المقاطع والتفاعل معها.
- مساعد لإنشاء محتوى تسويقي باستخدام Gemini.
- واجهة متجاوبة وإعداد Android عبر Capacitor.

## التقنيات

- **الواجهة:** React، TypeScript، Vite، Tailwind CSS
- **الخادم:** PHP API، مع Express/Vite لتشغيل بيئة التطوير
- **قاعدة البيانات:** MySQL
- **تطبيق الهاتف:** Capacitor وAndroid
- **خدمات اختيارية:** Firebase وGoogle Gemini

## المتطلبات

- Node.js وnpm.
- PHP CLI لتشغيل واجهة API محليًا.
- خادم PHP وقاعدة MySQL لنشر وظائف الخادم.
- Android Studio وAndroid SDK عند تطوير نسخة Android.

## الإعداد والتشغيل المحلي

1. استنسخ المشروع وثبّت الاعتماديات:

   ```bash
   git clone https://github.com/aymencharaf/youmi-gro.git
   cd youmi-gro
   npm ci
   ```

2. جهّز إعدادات PHP:

   أنشئ `public/config.php` اعتمادًا على `public/config.example.php`، ثم أدخل بيانات قاعدة البيانات وإعدادات المدير ومفاتيح الخدمات المطلوبة. لا تستخدم كلمات المرور أو القيم الافتراضية في بيئة الإنتاج.

3. (اختياري) اضبط متغيرات البيئة في ملف `.env` عند الحاجة، مثل `GEMINI_API_KEY` لاستخدام Gemini. لا تضع أسرارًا حقيقية في ملفات الواجهة أو ترفعها إلى المستودع.

4. شغّل التطبيق:

   ```bash
   npm run dev
   ```

   يعرض Vite الواجهة، ويشغّل `server.ts` خادم PHP محليًا ويوجّه طلبات `/api.php` إليه. تأكد من أن أمر `php` متاح وأن إعداد MySQL صحيح. افتح عنوان localhost الذي يظهر في الطرفية.

## أوامر المشروع

| الأمر | الغرض |
|---|---|
| `npm run dev` | تشغيل بيئة التطوير |
| `npm run lint` | فحص أنواع TypeScript |
| `npm run build` | إنشاء نسخة الواجهة الإنتاجية في `dist/` |
| `npm run preview` | معاينة نسخة Vite المبنية |
| `npm run android:sync` | بناء الواجهة ومزامنتها مع مشروع Android |
| `npm run android:open` | فتح مشروع Android في Android Studio |
| `npm run android:run` | تشغيل التطبيق عبر Capacitor على جهاز/محاكي Android |

> أمر `npm start` في إعداد المشروع لا يشغّل خادم الإنتاج؛ فهو يعرض تنبيهًا بأن استضافة الإنتاج تعتمد على PHP/Apache.

## قاعدة البيانات وواجهة PHP

يحتاج الخادم إلى PHP وMySQL. أنشئ قاعدة البيانات، واضبط `public/config.php`، ثم طبّق ملفات الترحيل المناسبة **مرة واحدة** على قاعدة البيانات الصحيحة:

- `reels_database_migration.sql` — جداول المقاطع والإعجابات والتعليقات.
- `database_admin_migration.sql` — تحديثات مرتبطة بحسابات الإدارة والمستخدمين.
- `tenant_migration.sql` — جدول ربط المتاجر بقواعد بيانات المستأجرين في قاعدة البيانات المركزية.
- `tenant_database_schema.sql` — بنية البيانات لكل قاعدة مستأجر.

قد تنشئ واجهة API بعض الجداول تلقائيًا عند توفر الصلاحيات، لكن ذلك لا يغني عن مراجعة إعداد قاعدة البيانات والترحيلات قبل النشر. اختبر تسجيل الدخول والمنتجات والطلبات والاشتراكات بعد الإعداد.

## النشر

### الويب

أنشئ ملفات الإنتاج باستخدام `npm run build`، ثم انشر ملفات الواجهة وملفات PHP على استضافة تدعم PHP وMySQL. تأكد من توافق مسارات API مع إعداد النشر؛ فالواجهة تطلب `/api.php` من نفس الأصل. لا ترفع إعدادات محلية أو أسرارًا، وراجع صلاحيات الملفات والمجلدات وسجلات PHP بعد النشر.

### Android

إعداد Capacitor الحالي يستخدم المعرّف `com.youmi.gro` ويشير إلى الموقع المنشور `https://youmi.wuaze.com`. لمزامنة التغييرات وفتح مشروع Android:

```bash
npm run android:sync
npm run android:open
```

راجع `capacitor.config.ts` قبل تغيير عنوان الموقع أو إعدادات التنقل. اختبر التطبيق على جهاز أو محاكي بعد البناء، بما في ذلك اتصال API وتسجيل الدخول.

## إعدادات الأمان

- لا ترفع `public/config.php` أو ملفات `.env` المحتوية على أسرار.
- غيّر بيانات المدير الافتراضية في إعداد PHP قبل إتاحة الموقع للمستخدمين.
- لا تستخدم مفاتيح خدمات أو بيانات قاعدة بيانات حقيقية في الكود المرسل إلى المتصفح.
- احتفظ بنسخة احتياطية من قاعدة البيانات قبل تطبيق أي ترحيل.
- تحقّق من صلاحيات المستخدم على الخادم لكل عملية إدارية أو حساسة.

يسعدنا استقبال التحسينات والإصلاحات. قبل إرسال التغييرات، شغّل:

```bash
npm run lint
npm run build
```

واختبر يدويًا الوظائف المرتبطة بالتغيير، خصوصًا واجهة API إذا كان التعديل يمس PHP أو قاعدة البيانات.
